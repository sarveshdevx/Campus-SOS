The Core Challenge

The Realities of Campus Safety Breakdown

Why traditional university emergency response fails students and dispatchers

1. Delayed Response

Traditional call desks and paper logs create routing friction. In sudden medical emergencies or security threats, every minute of manual coordination compounds risk.

2. Under-Reporting

Up to 80% of hazing, bullying, and harassment concerns go unreported due to fear of retaliation, academic exposure, or lack of verified confidentiality.

3. Siloed Operations

Campus security, clinic paramedics, and facilities operate in separate silos. Multiple calls for the same event create chaos without automated correlation.

System Solution

Dual-Pathway Safety & Specialized Roles

Architecturally isolating emergency response from routine concern intake

Pathway A: Emergency SOS
  • Persistent one-click floating action button across the portal.
  • Sub-millisecond deterministic dispatch (< 4ms).
  • Zero AI dependency: Life safety never waits on external LLM APIs.
  • Instant concurrent routing to on-duty Security and Medical teams.
Pathway B: Routine & Confidential Intake
  • Structured intake across 6 campus safety disciplines.
  • Three-tier privacy: Identified, Anonymous, and Confidential.
  • Multi-factor duplicate candidate matching with human review.
  • Transparent chronological timeline for student tracking.

Triage Algorithm

Multi-Factor Incident Matching & Human Review

Transparent mathematical similarity with zero automated deletions

Score = (0.25 × Category) + (0.35 × Location/Haversine) + (0.20 × Temporal Window) + (0.20 × Lexical Jaccard)
🔍 Weighted Heuristic Factors
  • Category (0.25): Strict match across 6 safety categories.
  • Location & GPS (0.35): Landmark matching + sub-50m Haversine distance.
  • Temporal Window (0.20): Scaled decay within 30 to 180 minutes.
  • Lexical Overlap (0.20): Non-stopword Jaccard token similarity.
🛡️ Human-in-the-Loop Safeguard
  • Threshold ≥ 0.60 flags duplicate candidate for review.
  • Zero Auto-Deletion: Algorithm only recommends; dispatchers make the final decision.
  • MySQL Check Constraint: Enforces incident_a_id < incident_b_id to eliminate duplicate reversed pairs and self-matching.

Security & Reliability

Application Security & Resilient Fallback

Defense-in-depth protection and offline operational continuity

🔐 Core Security Controls
  • Role Escalation Prevention: Public registration strictly provisions student role; client overrides are ignored.
  • Session Fixation Protection: Session ID regenerated on login (session_regenerate_id(true)).
  • Anti-CSRF: 64-character token required on all state-changing endpoints.
  • Exception Sanitization: Generic error messages prevent database credential or stack trace leaks.
⚡ Deterministic Heuristic Fallback
  • Zero Delay: If Gemini is offline, disabled, or times out (3.0s), local keyword heuristics classify emergency instantly.
  • 100% Submission Guarantee: External AI failures never block incident creation or SOS dispatch.
  • Zero Secrets in Frontend: API keys and DB credentials exist solely in backend/.env outside the public web root.
